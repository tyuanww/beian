# 版本、身份与设置合同

本文件保存原 AGENTS 的对应工程合同，仅在涉及本主题时读取。产品行为不构成执行作业、发送消息或操作生产的授权。日期与验收状态是记录时快照，当前结论须绑定本次证据。路径除链接外均相对仓库根。

升 VERSION 时：`VERSION` 文件和 `apps/web/server/src/index.ts` 里的 `VERSION` 常量必须同号。`package.json` 只写三位（npm 不认第四位）：MICRO（`0.12.8.0` → `0.12.8.1`）三位不动；PATCH/MINOR/MAJOR 才改三位。4 位号，记录时版本线为 `0.21.x.0`；实际基线读当前 `VERSION`，不得据此降版。用户点名大版本才跳 MINOR。开放 PR 的 VERSION 若落后于 `main`，不合；先 `/ship` 重占号。

杭州机箱管理员必须在生产数据目录 `users.json` 中用真实飞书 `open_id` 显式绑定 `role: "admin"`，才能扫描 Blender / Illustrator（含 PATH）。姓名、花名和显示名只展示，绝不参与提权；同企业首次登录一律是 `reviewer`。删除账号、设 `disabled: true` 或调整角色后，已有飞书会话在下一次请求立即撤销或同步，不要求重新登录；公网模式还必须撤销并落盘清除旧显示名会话。退出直接删 token，不得因账号目录暂时不可读而保留。伸美其他人默认审稿员：能进审稿台，不能扫本机 exe。2026-08-24 当周曾决定不做品牌登录闪屏、申请权限工单（office-hours D1=A）；未有新决定前不主动扩展，相关新请求出现时再核对范围。

飞书推送不必装 lark-cli。点「发一条测试」用已填的飞书应用发给**当前登录**；成功才打开 `FEISHU_ENABLED` 并在空时写入 `FEISHU_OPEN_ID`。`lark_send` 走 `POST /api/settings/probe`，权限见下文 0.31.1.14 一节。开工板绿 ≠ 籽烨已收到。「发一条测试」只发给点按钮的当前登录管理员，不能代发给别人；`FEISHU_OPEN_ID` 为空时，第一次测试成功会把接收人写成这位管理员，所以要先填好接收人再测。真实通知（签字完成、对照/打样完成或失败、Illustrator 看门狗告警）都不指定收件人，统一发给 `FEISHU_OPEN_ID` 这一个人，且只在 `FEISHU_ENABLED` 打开时发送。要确认籽烨作为审稿接收人能收到：管理员核对 `FEISHU_OPEN_ID` 填的是她，再由她确认收到下一条真实通知。不要把开关 / open_id / bot 当主路径让人手填。探测 id `lark_send` 的 pending/结果必须画在行 `lark`，否则按钮看起来没反应。

MiniMax 未开语义复核是「未用」，不是「可用」；探测是 `GET /v1/models`，不是对话也不是余额。百度 OCR 绿 = 对照同款识别接口通了，不是静默授权。已通的密钥默认折叠，点开才改。

开工板是线性进度 + 7 行清单，不要画成圆环仪表，不要用「通 / 不通」当状态字。界面单测只测纯函数，不引入 RTL。

## 设置接口按角色裁剪（0.31.1.14）

实现：`apps/web/server/src/settings.ts` 的 `publicView({ admin })`、`trimFieldForNonAdmin`、`nonAdminHealth`；路由在 `apps/web/server/src/index.ts`。未登录一律 401（`need()`），角色取自当前会话；会话每次查找都按账号目录重读角色（`apps/web/server/src/auth.ts` 中 `account.role !== s.role` 时同步并落盘），管理员被降级后下一次请求即按新角色裁剪或 403。

- `GET /api/settings`：管理员返回不变。非管理员（reviewer / viewer）每个字段保留元数据 `key`、`label`、`kind`、`help`、`restart`、`adminOnly` 和 `set`；除 `kind: "toggle"`（`WB_PUBLIC`、`WB_DEV_DISPLAY_LOGIN`、`FEISHU_ENABLED`、`MINIMAX_ENABLED`）与 `WB_MAX_UPLOAD_MB` 外，`value`、`last4` 两个键整体省略，不返回空串或 null。`derived` 只剩 `tenant_key_filled`（去掉 `redirect_uri`、`python`）；`health.mockup.detail` 在已配置时改为「已配置 Blender」，不含路径，其余 `health` 项原样。队列等其余顶层字段不变。
- `POST /api/settings/probe`（含飞书「发一条测试」`lark_send`）、`GET /api/settings/billing`、`POST /api/settings/billing/refresh`：非管理员 403。`POST /api/settings` 原本即仅管理员，返回的视图按管理员口径。
- 已接受的低风险：非管理员仍能从 `set` 看出哪些密钥/字段已填，看不到值和末四位。
- 有意的行为变化：reviewer 不能再自己点飞书「发一条测试」，只能由管理员测。
- 任务报错按角色脱敏（`apps/web/server/src/pathRedact.ts` 的 `redactLocalPaths`）：
  - 处理顺序：① 整条报错（含网址）先把 `%5C` / `%2F`（大小写不限）还原成 `\` / `/`；套在分隔符外的 `%25` 逐层剥掉，最多 3 层（`%2F`、`%252F`、`%25252F`），解到 3 层仍残留的 `%…2F` / `%…5C`（任意层 `%25`）直接当分隔符（`%2525252FUsers%2525252Fbob` → `本机路径`）；不紧挨 `2F` / `5C` 的 `%25` 不变（`进度 50%25 完成` 不变）；② 对还原后的整条报错脱敏，不先截断；③ 脱敏结果超过 8000 字符只保留前 8000 字符，截断点落在表情等代理对中间时保留前 7999 字符，并在末尾追加「（后面省略）」；④ 非管理员和飞书出口再做兜底检查（见下文「兜底隐藏」）。
  - 网址：只有 `http://`、`https://`（大小写不限）算网址，网址普通部分到空白、引号（`"` `'`）、反引号、尖括号或任何非 ASCII 字符为止。协议和主机（含端口、IPv6）保留；主机前的用户名密码（`user:pass@`、`user@`，取主机前最后一个 `@`）整段换成 `***@`。主机之后夹带的路径从起点一直替换到 `&`、`#`、`?`、空白、引号、反引号、尖括号或中文标点为止，中间的中文和 emoji 不算终点，终点之后的参数保留：以 `/` 开头的已配置数据 / 工具目录，以及 `/Users/`、`/home/`、`/root/`、`/var/folders/`、`/private/var/`，换成 `/本机路径`（保留前导斜杠）；Windows 风格的已配置目录、盘符路径（`C:\` / `C:/`）与反斜杠路径换成 `本机路径`（无前导斜杠）。空格和中文标点的续接规则与网址外相同：遇到空格或中文标点后，到下一个空白前还有分隔符就继续当路径（Windows 写法文件名里的一个空格也算在路径内）。例：`http://x/?p=/Users/bob/my docs/secret/a.pdf` → `http://x/?p=/本机路径`；`http://x/srv/tools/bin/blender/a.pdf` → `http://x/本机路径`；`http://x/open?f=/srv/tools/bin/blender/a.pdf&q=1#h` → `http://x/open?f=/本机路径&q=1#h`；`http://x/?p=D:\Tools\blender.exe&q=1` → `http://x/?p=本机路径&q=1`；`http://x/?p=C:\Users\bob\a.pdf&q=1` → `http://x/?p=本机路径&q=1`；`http://x/C:/Users/bob/a.pdf` → `http://x/本机路径`；`https://h/f?path=/home/bob/a.pdf#x` → `https://h/f?path=/本机路径#x`；`http://x/Users/张三/a.pdf` → `http://x/本机路径`；`http://bob:s3cr3t@x/Users/bob/a.pdf` → `http://***@x/本机路径`；`http://x/?f=%252FUsers%252Fbob%252Fa.pdf` → `http://x/?f=/本机路径`；`http://x/?f=C:\Program Files\x\a.pdf` → `http://x/?f=本机路径`；`https://example.com/api/v1/x.json`、`mail=a@b.com` 不变。`x://`、`foo:///`、`git+ssh://`、`file://` 不算网址，按普通路径扫描（`file://` 先去掉前缀）。
  - 其余文本：① 替换已知本机路径（`DATA_DIR`、`PYTHON`、`pythonBin()`、`blenderBin()`、`illustratorBin()`，按长度从长到短，可含空格）；末段像文件名（带 1–8 位扩展名）换成文件名，否则换成「本机路径」，紧跟其后的子路径只留文件名。② 其余路径去掉本机目录、只保留文件名，无文件名的目录写成「本机路径」。覆盖：Windows 盘符路径 `X:\` / `X:/`（含小写盘符，盘符前不能紧贴 ASCII 字母数字，所以 `abc:\x\y.pdf` → `abc:y.pdf`；目录名可含空格，只要空格后的词在新路径起点、空白或标点之前还有分隔符，如 `C:\Program Files\客户 新品\a.ai 打不开` → `a.ai 打不开`）、UNC `\\server\share\...`（含 `\\?\`，空格规则同 Windows）、无盘符的反斜杠路径（至少一级目录；末段带扩展名时只留文件名，如 `\Users\bob\a.pdf` → `a.pdf`；只有目录时换成「本机路径」，如 `\Users\bob\Desktop` → `本机路径`，但至少要有一段目录名不少于 2 个字符，所以 `\n`、`\t` 这类单字母转义不动）、至少含一级目录的 Unix 绝对路径（`/Users/...`、`/home/...`、`/var/folders/...` 等，前一个字符不是 ASCII 字母数字或 `. _ - ~ / \`，所以紧贴中文也算，相对路径如 `docs/x.md` 不动）、`~/...` 与 `~用户名/...`，以及可含空格的已配置数据目录、Python / Blender / Illustrator 路径。斜杠写法和 Windows / UNC 路径遇到空格或中文标点时，到下一个空白前若还有分隔符，就继续当路径（`at /home/bob/My Project/x.ts:12:5` → `at x.ts:12:5`，`/Users/bob/【内部】/a.pdf` → `a.pdf`，`/Users/bob/a，b/c.pdf` → `c.pdf`）；否则路径在空格或标点处结束。Windows / UNC 文件名可含一个空格：空格前的末段没有扩展名、空格后的词以扩展名结尾时合成一个文件名（`\\nas\share x\a b.pdf` → `a b.pdf`），只认一个空格。文件名在空白、引号、括号和中英文标点处结束；扩展名后紧跟中文时到扩展名为止；堆栈里的 `x.ts:12:5` 保留行列号；替换结果与紧贴的中文之间补一个空格（如 `打开/tmp/abc/a.pdf失败` → `打开 a.pdf 失败`）。网址以外是单趟线性扫描（无回溯正则），5000+ 字符对抗输入各 <50ms。例：`step 2/3` 不变，`C:\supply\data\x\a.pdf` → `a.pdf`，`%252Fhome%252Fbob%252Fa.pdf` → `a.pdf`，`目录 /a/b 不可写，见 docs/x.md` → `目录 本机路径 不可写，见 docs/x.md`。
  - 已知缺口：斜杠写法只有最后一段文件名含空格或中文标点时，露出后半截文件名（`/Users/bob/my docs/a b.pdf` → `本机路径 b.pdf`，`/home/bob/a，b.pdf` → `本机路径，b.pdf`），目录名不再露出；网址里百分号编码的用户名密码原样输出（`http://bob%3Apw%40x/a` 不变，兜底也不拦）；全角斜杠 `／`、`＼`、`∖` 不当分隔符（`a／Users／bob` 原样，兜底也不拦）；超长 UTF-8 `%c0%af`、HTML 实体 `&#47;` 不解码（原样，兜底不拦）；路径被换行断开时只认换行前半截（`/Users/bob/a` 换行 `b.pdf` → `本机路径` 换行 `b.pdf`）；`ftp://` 等非 http(s) 网址按普通路径处理（`ftp://h/Users/bob/a.pdf` → `ftp:a.pdf`）；查询参数名必须正好是凭据词或用 `_` `-` `.` 接在后面才拦，`apikey=` 这类连写不拦。已知副作用：`%2F` / `%5C`（含 `%252F` 等多重编码）整条报错一起解码，非路径文字也会变（如 `进度 50%2F100` → `进度 50/100`，网址里的 `%2F` 同样被解开）。已知取舍：Windows / UNC 末段无扩展名、空格后的词以扩展名结尾时也会合成文件名（`C:\x\dir see.log` → `dir see.log`）；报错里字面的 `\nfoo\nbar` 这类转义串会被当成反斜杠路径换成「本机路径」，只剩一段的 `\nfoo` 脱敏后不变、再被兜底整条隐藏（单字母 `\n`、`\t` 不受影响）；查询参数名像凭据时即使值无害也整条隐藏；8000 字截断落在占位词中间时留半截占位词；打样单报错（含兜底后）只留前 80 字；网址路径里出现 `/Users/`、`/home/`、`/root/`、`/var/folders/`、`/private/var/` 时，即使是公开网站也会被替换（`https://example.com/Users/list` → `https://example.com/本机路径`）。
  - 任务详情（各路由经 `publicTask(task, viewerFromSession(s))`，`apps/web/server/src/jobs.ts`）与任务列表（`/api/tasks`，`apps/web/server/src/tasks.ts`）里的 `error` / `job_error`：非管理员经 `guardErrorFields(task.id, …)` 返回脱敏文本并做兜底检查；管理员（`viewerFromSession` 的 `admin: session.role === "admin"`）看原文，不带 `error_hidden` / `error_ticket`；`publicTask` 未传 viewer 时按非管理员处理。`/api/history` 不返回报错字段。
  - 飞书失败通知（对照任务 `fireTaskNotify`、打样 `fireMockupNotify`）里的报错一律经 `guardNotifyError` 脱敏并兜底，与收件人角色无关；单号分别是 `task.id` 和打样 `job.id`（12 位十六进制）。
  - 打样单列表 `/api/mockups` 与详情 `/api/mockups/:id`（`mockup.ts` 的 `publicMockupSummary` / `publicMockup`，`index.ts` 按 `s.role === "admin"` 传 `admin`）里的 `error`、`job_error`、`render_mutation.error`：非管理员按顺序 ① `publicMockupError`（客户稿件名换成「稿件文件」、盘符 / UNC / 斜杠路径换成「本机稿件」，含网址或凭据字样整条换成「打样失败，请让管理员在本机检查详细原因」，只留前 80 字）→ ② 脱敏 → ③ 兜底（`guardErrorFields(job.id, …)`）→ ④ 再只留前 80 字。三个字段任一触发兜底时，三个都换成「任务失败，请联系管理员（单号 <job.id>）」，并加 `error_hidden: true` 和 `error_ticket`（= `job.id`）。管理员不变，只走 `publicMockupError`，不带这两个字段。例（非管理员）：`读取 ~/secret/id_rsa 失败`、`读取 \users\bob 失败`、`读取 %2fUsers%2fbob 失败`、`读取 %252fUsers%252fbob 失败` → `读取 本机路径 失败`（未触发兜底）；`读取 \Documents and Settings\bob 失败` → 三个字段都是「任务失败，请联系管理员（单号 <job.id>）」。
  - 现行行为（待定）：渲染代际提交接口返回的 `mutation.error`（`jobs.ts` 的 `publicMutationResult*` 调 `publicRenderMutation` 不传角色）一律按非管理员规则输出，管理员在这一处也看不到原文。
  - 兜底隐藏（`pathRedact.ts` 的 `guardPublicError` / `guardNotifyError` / `guardErrorFields`）：上述出口在脱敏、截断之后，若文本仍含下列任一特征，就整条隐藏：`/Users/`、`/home/`、`/root/`、`/var/folders/`、`/private/var/`（大小写不限；`a/root/b` 这类也算，宁可误伤）；`~/`、`~用户名/`（`~` 前不是 ASCII 字母数字，单独的 `~`、`~3 秒` 不算）；UNC `\\服务器\`；`\Users\`（大小写不限）；反斜杠后跟至少 2 个字母（`\Settings`、`\bob`；单字母转义 `\n`、`\t` 不算，`\nfoo` 算，这是已知取舍）；查询参数名是 `password` / `passwd` / `pwd` / `pw` / `token` / `secret` / `key`，或用 `_` `-` `.` 接在这些词后面（`api_key`、`access_token`、`client_secret`、`x-token`），大小写不限，`?monkey=1`、`?keyword=x`、`?tokens_left=3` 不算；盘符 `X:\` / `X:/`（前一个字符不是字母，所以 `http://` 不算）；`%2F`、`%5C`；网址里的 `://用户名:…@`（`@` 之前没有 `/ ? #` 或空白）；已配置的数据 / 工具目录原文。`http://host:8080/x 失败` 不触发。兜底文案分两种：页面 / 接口（任务、打样单）是「任务失败，请联系管理员（单号 <编号>）」；飞书失败通知是「任务失败，原文已隐藏，请到后台查看（单号 <编号>）」。接口里任一报错字段触发时，所有报错字段都换成这句话，并加 `error_hidden: true` 和 `error_ticket`（纯编号）；未触发时不加这两个字段。例：`a/Users/bob` → `{"error":"任务失败，请联系管理员（单号 t1）","job_error":"任务失败，请联系管理员（单号 t1）","error_hidden":true,"error_ticket":"t1"}`；`C:\Documents and Settings\bob`、`http://u@h/?password=pw`、`http://h/?pw=secretpw`、`x \nfoo` 整条隐藏；`/root/x.log 打不开` → `x.log 打不开`、`\\server\share\a.pdf` → `a.pdf`（已脱敏，不触发）。
  - 未纳入、未审计（可能仍带出本机路径）：`apps/web/server/src/index.ts` 全局错误处理对 4xx 原样返回 `err.message` 作 `detail`；Illustrator 看门狗飞书告警（`notifyIllustratorWatchdog`）；打样 `print_faces_repair.error`；`apps/web/backend` worker 输出与其他 HTTP `detail`。跟进见 TODOS F10。
