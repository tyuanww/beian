## 2. 最终交互

### 2.1 打样结果与 2D 展开图

- “2D平面图”下顺序固定为：**2D展开图 / 正面 / 反面 / 左侧 / 右侧 / 顶部 / 底部**；默认可查看完整展开稿，切换单面不丢当前打样单。
- 展开图保留各面在源稿中的位置、方向、比例，包含无印刷内容的粘口、插舌及上下封口。去除刀线、折线、尺寸和制作标注；属于印刷画面的装饰线保留，不能仅按线色或线宽删除。
- 展开图独立提供“下载展开图 PDF”，按源稿物理尺寸 **1:1** 输出。预览缩放不改变下载尺寸；不缩到 A4、不裁掉结构。提示按“实际大小 / 100%”打印，并使用能容纳完整展开稿的纸张。
- 单面提供 PNG，“下载六面 ZIP”仅包含六面。缺面不称整套完整；展开稿和六面分别显示可用性及原因。
- 优先复用同源、同代际且经完整性核实的净版源件；需要补导出时走现有 Illustrator 队列。禁止六面拼图、GLB 截图冒充源展开稿，也不为下载重跑 Blender。
- 源件丢失、辅助内容无法可靠分离或完整几何无法证实时，明确不可用及可采取的补源操作，不展示虚假的“可打印折盒”。旧单依据实际源件能力处理。

### 2.2 文件压缩

导航顺序：审稿台 → 打样台 → 文件压缩 → 历史记录 → 设置。选择/拖入文件后显示清单，开始上传后冻结这批文件集合；先显示上传进度，服务端接收并持久化后才显示后台排队/压缩。上传未完成时不能承诺关闭浏览器仍会继续上传。

批次详情逐文件显示原始大小、结果大小、节省比例、状态和原因。已符合要求显示真实零压缩；部分成功可下载成功项及原字节直出项，失败项保留原因和下一步。无可下载项时不生成空 ZIP。重试只处理服务端允许的失败项，保留已有成功结果。

图片首版支持 JPG/PNG/WebP，自动尽量减小且保留清晰度，不新增用户未要求的图片目标大小控件。PDF 保持 PDF 输出；10MB 是单份 PDF 的门槛，不是整批 ZIP 门槛。

### 2.3 统一历史与大量记录

- 默认全部时间、最新在前；每页展示 10 条。类型、状态、创建人、日期和关键词可以组合；提供近期/全部/自定义日期、无效日期提示、清空筛选和空结果恢复。
- 关键词匹配品名、批次名和批次内原文件名，查询全部有权限记录；展示命中的文件名。默认批次标题从文件名摘要生成，避免大量“新建任务”。本批不增加文档正文全文检索。
- 状态选项随类型变化，明确压缩的部分成功/未达标和审稿的待确认，不把不同业务状态强行等同。
- 进入详情再返回，保留查询、页码和原记录位置；查询变化时重置分页游标。偏好和恢复数据按登录用户隔离，失效记录有明确提示。
- 列表加载失败显示错误并保留上一份有效列表；不得将失败伪装为“暂无记录”。统计和筛选计数使用同一权限及查询口径，不以当前页数量冒充总数。

### 2.4 右侧核对栏与连续审稿

- 初始宽度 **448px**；用户可在 320–560px 范围调整。桌面可用工作区宽度为 W 时，保留画布至少 480px 与分隔条 8px，侧栏最大值为 `min(560, W-488)`。
- W≥808px 使用左右布局；W<808px 改为上方画布、下方问题，画布高度 240–420px，短屏允许页面纵向滚动。≤1024px 先折叠左导航，≤720px 左导航用抽屉。窄屏临时布局不覆盖用户保存的桌面宽度。
- 右栏提供上一项/下一项、仅看待确认、疑点目录及下一待确认；20 项以上也能快速定位。跳转待确认时跳过已处理项。长地址、配方等内容可读，人工结论和备注紧邻对应证据。
- 桌面右栏内容独立滚动，操作始终可达；只标当前字段，调整宽度或折叠后保持该字段可见。无 bbox 不画假框，沿用既有定位、缩放及 SVG/PNG 回退。
- 宽度/折叠状态使用新设置键，按用户及版本隔离；不迁移旧浮窗 x/y。分隔条可键盘调整，焦点和当前疑点保留；触控目标至少 40px，适配 13–28px 字号。
- 人工结论保存成功才显示成功。已知保存失败明确提示；保留既有服务端结论与本地未提交草稿的区别，不丢备注。现有签字、对红及 `hits_v2` 规则保持。

## 3. 实现结构与接口边界

### 3.1 复用位置与新增职责

| 位置 | 实施职责 |
|---|---|
| `apps/web/ui` | 右栏和连续核对；打样七标签与下载；压缩页面；历史组合查询和返回恢复 |
| `apps/web/server` | Hono 权限与公共接口；上传 receipt；持久作业、调度和排干；安全资产下载；历史摘要查询 |
| `apps/web/backend` | 沿既有 CLI 对照链融合 PDF/OCR/原生文字证据，不新增 HTTP 壳 |
| `workers/packaging` 与既有 Illustrator 宿主 | 净版完整展开导出、候选文字提取；共用单槽、请求代际和关闭确认 |
| 新压缩执行模块 | 隔离 Sharp 子进程、qpdf 和本地 Java/PDFBox helper；隐藏进程、资源、候选策略及内部路径 |

沿用已有上传、作业和资产模块的耐久语义；新逻辑按压缩用例收敛，不把格式解析塞入 Hono 请求线程，也不把每个动作拆成转发包装层。

**开源实现方向保持不变：**图片采用 Sharp，PDF 借鉴 Stirling-PDF 许可明确的 MIT `app/core` 目标大小处理逻辑，采用小型 PDFBox helper + qpdf。实施时固定实际版本/提交、许可和声明，排除商业 `engine` 及受限 API。完整 Stirling 站点会额外引入身份、部署和历史边界，本批不采用。此前调研不代表最新星数或运行兼容性已经验证。

### 3.2 计划新增/扩展的产品接口

以下为实施合同，具体命名以现有路由惯例收敛；不得误认为已经存在。

| 边界 | 行为 |
|---|---|
| 压缩上传目的 + `/api/compressions/start` | 使用既有分片 receipt；校验权限、能力和资源，幂等接收持久任务 |
| 压缩 list/detail、retry、`files/:key`、zip、终态 delete | 同一错误目录、`can_retry`、结果版本和产物白名单；安全字段投影 |
| 统一只读历史查询，计划 `GET /api/history` | 统一权限、筛选、排序、摘要、游标及可信统计；继续使用现有各类持久记录 |
| 打样资产清单 | 新增独立净版展开资产，绑定源 hash、代际、物理尺寸及完整性结果；六面标识不变 |
| Illustrator 请求/结果协议 | 新增/扩展能力版本及请求种类，原生候选结果与安全关闭确认分开 |

`admin/reviewer` 可创建；viewer 只读/导出。团队读取沿既有可见范围，修改、重试、删除同时满足角色和 owner/admin 条件。上传恢复仅本人；使用稳定身份，不以显示名鉴权。HTTP 不暴露本地路径、PID 或内部私有字段。

### 3.3 持久任务、资产与查询

压缩任务保存 owner、创建时间、source receipt、源身份/hash、revision、attempt、策略版本、目标字节数和逐文件状态/产物 key。批次状态由文件状态汇总，成功产物不可变。

接收顺序：预留 claim → 冻结/复制源并核 hash → 原子持久化 queued manifest → 提交 claim → 入队；重启按 receipt 幂等恢复。初始化后由 jobs 单一写入者推进。worker 只产出当前 attempt 结果；旧回调不得覆盖新 revision，删除 tombstone 防止复活。

原子发布使用受控目录、同目录独占临时文件、flush/fsync 和 rename；不以 Windows 复制覆盖或先删旧文件降级。rename 失败保留旧记录。下载仅引用已发布 manifest，不能在候选未验证时暴露结果。

历史目前由前端聚合已有类型；新增压缩分页本身不能满足“所有类型的全量检索”。本批需建立**最小统一摘要读模型与查询入口**：复用各类权威记录，索引仅存搜索/列表需要的字段及子文件名，不迁数据库。更新由对应持久写入路径串行/原子发布；存量索引可分段重建，不能每次列表请求扫描和解析全部原文件/任务。

查询按 `(created_at, type, id)` 稳定排序，游标绑定筛选、用户可见范围和首屏时间边界。API 默认每批 50 条、最多 100 条，UI 10 条一页按需读取；跳转未取得游标的页面不能用一次拉完整库实现。统计仅在索引完整可信时提供；未知或损坏索引明确不可用/503，不返回假空列表或假总数。客户端压缩列表缓存最多 3 个 API 页，仅轮询当前批次及当前可见活跃记录。

源文件及结果沿现有长期保存、同权限手动删除策略；本批不引入自动清理。流式下载使用背压和读租约，断连/错误 finally 释放；删除先 tombstone，再等读租约结束，活跃作业不提供假取消或强删。

## 4. 三条核心处理链

### 4.1 完整净版展开链

同源 `.ai`/generation → 核实完整净版资产及结构 → 必要时由原生宿主导出副本 → 校验物理尺寸、面位置及粘口/封口 → 发布独立 PDF → 预览/下载。隐藏辅助内容仅改变可见输出，结构几何继续参与校验。

不修改源件。必须核实已有净版资产是否真的包含完整展开几何；单面纹理或只含印刷区域的裁切图不满足。实施时同步成片合同中旧“无 PDF 下载”边界，新增范围只限本次明确要求的净版展开 PDF。

### 4.2 压缩链

1. 在受限子进程中检查格式 magic、可读性、权限、结构及资源；文件已小于门槛也不能跳过可读预检。首版不收密码，不处理动图/多帧为静态首帧。
2. PDF 结构化判断数字签名/修改限制，检查已填充签名字典、签名上下文 ByteRange/Contents、DocMDP 和可访问的增量签名修订。空签名域、印章图片、Stamp 注释不等于已签；判断不明不重写。这里不验证签名真实性或有效性。
3. 可读且小于 `10,000,000` 字节的 PDF 按原字节直出，包括带签名/修改限制文件。达到或超过门槛的签名/受限文件拒绝重写，保留原件；不以只保留章外观换取达标。
4. 可重写 PDF 先 qpdf 无损优化，再从原件按预定高保真到低保真档位生成有限候选。第一份通过内容/结构/质量底线且实际字节 `<10,000,000` 的候选立即发布并停止；9,950,000 字节也应停止。9,800,000 只是估算余量，不是第二道门槛；不假设体积单调。
5. 不整页栅格化、灰度化、删页或拆页冒充达标。页数、顺序、尺寸、文字、矢量、透明、彩色章、骑缝章、条码与小字必须保留。安全质量底线仍超标则 `unmet_target`，不提供伪成功。
6. 图片格式/ICC/透明度保留；重编码时按 EXIF 1–8（含镜像）归一可见方向，再移除或归一 EXIF/XMP 方向，避免二次旋转。90/270 度允许存储宽高互换；无收益则原字节直出。

qpdf 结果按具体命令解释：普通转换/检查 0/2/3 分别代表干净成功/错误/警告，加密探测另按其语义。禁止隐藏警告；版本化警告白名单 v1 为空，未经批准的警告不发布。后续允许项需夹具证明内容不受影响。

### 4.3 原生文字与误报整改链

标准 PDF/OCR 主链保留；对需要 Illustrator 私有编辑数据的输入，使用物理副本、源 hash、attempt 和提取器版本，经现有单槽宿主取得文字候选及画板/页、坐标变换、对象标识、可见性和字体信息。提取前后源 hash 必须一致，不保存改动到原稿。

原生文字、OCR 和可见画面证据都保留。隐藏、旧稿、画板外、裁剪、缺字体或无法确定可见性的候选不得直接判定；bbox 重叠不等于文字相同。只有可证明对应同一可见文字且 OCR 确实读错时才纠正识别，再进入既有业务规则；不能直接改成“一致”。混合图文区域不能因有少量原生活字而整区跳过 OCR，冲突转人工。

Illustrator 与打样共用 FIFO 单槽；原生前置阶段不占 OCR 执行槽。初值 120 秒仅为未执行时排队预算；进入打开/提取/写结果/关闭后沿既有 1260 秒生命周期及禁杀规则，不能在 120 秒到时放槽或删副本。

结果 JSON 不等于文档关闭：必须取得同 request/attempt/版本的文档关闭、桥接退出、无在途请求及锁可归还确认。未知则保持 active/faulted 围栏并计入排干，允许逻辑 OCR 回退但不并发重发原生请求，晚到结果不覆盖回退。不得杀共享 Illustrator，也不因单次 idle 心跳清 fault；恢复沿现有管理员流程。副本只在无执行者及文档引用被证实后清理，未知时保留并计磁盘。

稳定失败原因包括 `native_busy/offline/source_changed/close_unconfirmed`。对用户解释影响及下一步，不暴露 PID/路径。仅新增候选与回退而未改善金标误报，不等于 B01.5 交付。

## 5. 状态、重试与资源约束

逐文件状态：`queued/running/succeeded/passthrough/unmet_target/unsupported/failed`。批次任何文件运行中则 running，否则有 queued 则 queued；全部终态再汇总 done/partial/failed。失败项重新入队时已成功文件仍可下载。

| 原因类别 | 重试条件 |
|---|---|
| magic 不符、损坏、需密码、签名超标、修改受限、确定性内容无效 | 同一不可变原件不重试，换原件新建 |
| 签名不明、过滤器不支持、资源超限、未批准 qpdf 警告、目标未达成 | 仅相关且经验证的策略/工具能力改变后允许；改版本字符串不算修复 |
| 缺依赖/依赖不兼容、磁盘不足 | 修复且能力预检通过后允许；start 前失败不领取 receipt、不生成假已接单任务 |
| 超时/进程中断 | 旧执行者确认结束、无围栏且仍有预算才允许 |
| native 关闭未确认 | 不通过压缩重试或业务按钮清除宿主围栏 |

同源同策略最多额外 3 次人工重试，间隔至少 30 秒。重试用新 attempt 和策略快照；不可重试返回 409 与稳定原因，可受理首次返回 202，相同已受理 revision 的重放返回同一 attempt。服务端 `can_retry` 与按钮一致。

以下为保守实施初值，均需纳入策略版本；尚无本轮资源采证，不能写成已验证性能承诺。放宽需相关证据，策略收紧不追溯在途作业。

| 限制对象 | 初值/行为 |
|---|---|
| 上传 | 每批 ≤20 文件、总量 ≤100MiB、单文件 ≤100MiB；复用 1MiB 分片、两条流 |
| 连续源件占用/接单 | 每 owner 400MiB、全局 1GiB，覆盖未完成上传、receipt、已接收非终态源件连续核算；非终态每 owner 8 单、全局 64 单 |
| 图片/PDF 解析 | 每图 ≤32MP、含蒙版预计解码 ≤128MiB；每文件每轮解码流 ≤1GiB；PDF ≤200 页、展开后 ≤100,000 对象、Form 深度 ≤32 且去循环 |
| 执行 | 压缩独立并发 1；每 PDF ≤8 轮/5 分钟；初始质量底线 150dpi/quality 60，仍须人工质量验证 |
| 内存 | Java `-Xmx256m`；单压缩进程及专属子进程合计 RSS ≤768MiB；压缩工作组额外 ≤1GiB；Sharp/qpdf/helper 分阶段顺序执行 |
| 磁盘 | 每 attempt 临时与输出 ≤2GiB，单候选 ≤128MiB；扣除其他预留后仍须覆盖本次峰值预留及 2GiB 安全余量 |
| 原生 JSON | 读取前 ≤8MiB UTF-8，嵌套 ≤64、候选 ≤50,000；JSX 写出时计数，不截断伪成功 |
| 下载 | 每 owner 2、全局 4；无进展 120 秒、绝对上限 15 分钟，异常释放读租约 |

预检本身也可能耗尽资源，必须在解析前建立 OS 限制/监控，不能仅限制 Java 堆或解析后检查；无法强制预算的平台直接报告能力不可用。压缩子进程的终止机制不得用于共享 Illustrator。

所有新作业进入 queueSnapshot、重启恢复和 drain：排干阻止新接单/新下载，等待有界在途下载和作业；未知执行者/原生围栏不能报空闲。超出排干期限则中止本次切换、保留旧服务，不强杀共享宿主。固定可执行文件与 argv，路径由受控 source ID/产物 key 推导，文件名不进入 shell。

## 6. 执行顺序与完成门槛

这是执行分解，不是另一份当前状态清单。每步的实际完成证据回填 TODOS；不以文件创建或模拟成功关闭功能。

| 阶段 | 具体工作与产物 | 依赖及完成门槛 |

| M0 合同与技术入口 | 对齐最终交互；确定数据/错误目录、接口和能力版本；核实净版源件链、压缩依赖许可、原生 JSON/关闭协议；更新受影响设计及工程合同 | 先完成可独立的静态设计；真实样本实验仍按授权执行。三个技术关口不能靠假数据宣称通过 |

| M2 净版展开完整切片 | 同源净版导出与资产版本、1:1 PDF、七标签、六面 PNG/ZIP、旧单缺源提示 | 依赖 M0 源件/宿主合同；结构/尺寸/下载验证通过，最终还需代表真稿实际打印折盒 |
| M3 压缩与历史闭环 | 先持久接单/资源/恢复，再 Sharp/PDF helper，再压缩 UI、统一历史索引/全量查询、下载/失败重试 | R06/R07 一起接通；离页刷新、重启、部分失败、权限、索引恢复和大记录量验证通过；真实公章/小字质量单独验收 |
| M4 原生文字整改 | 宿主受控提取、可见性/坐标证据、OCR 融合、明确回退、人工真值对比 | 依赖 M0 和与 M2 一致的宿主协议；原件不变、无槽泄漏，指定误报改善且已知真差异不漏 |

M1 可先形成可见成果；M2/M3/M4 内部按单一行为切片，所有五项仍留在本批。共享 jobs、上传、历史查询及 Illustrator 协议变更需统一集成顺序，避免相互覆盖；不据此自动启动多 agent。

三个技术关口为：①完整净版的可靠分离及尺寸/折盒；②两类 PDF 的目标体积与可见内容保真；③原生文字与渲染的可靠对应及安全关闭。任一失败，应报告具体样本、限制与替代选择，保留未完成；不能悄悄把范围缩成六面图、仅图片压缩或仅 OCR 回退。
